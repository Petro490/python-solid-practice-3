class Rectangle:
    def __init__(self, width, height):
        self._width = width
        self._height = height
        
    def get_width(self):
        return self._width
        
    def set_width(self, width):
        self._width = width
        
    def get_height(self):
        return self._height
        
    def set_height(self, height):
        self._height = height
        
    def area(self):
        return self._width * self._height


class Square(Rectangle):
    def __init__(self, size):
        super().__init__(size, size)
        
    def set_width(self, width):
        self._width = width
        self._height = width
        
    def set_height(self, height):
        self._width = height
        self._height = height

Задача 5. Принцип инверсии зависимостей
Вам предоставлен код системы уведомлений, который нарушает принцип инверсии зависимостей. Ваша задача — отрефакторить код таким образом, чтобы он соответствовал принципу DIP.

Исходный код с нарушением DIP

class EmailSender:
    def send_email(self, recipient, message):
        print(f"Отправка email для {recipient}: {message}")


class SMSSender:
    def send_sms(self, phone_number, message):
        print(f"Отправка SMS на номер {phone_number}: {message}")


class NotificationService:
    def __init__(self):
        self.email_sender = EmailSender()
        self.sms_sender = SMSSender()
    
    def notify_user(self, user, message):
        if user.contact_preference == "email":
            self.email_sender.send_email(user.email, message)
        elif user.contact_preference == "sms":
            self.sms_sender.send_sms(user.phone, message)

Что нужно сделать

Проанализируйте предоставленный код и выявите нарушения принципа DIP.
Создайте абстрактный интерфейс Notifier для отправки уведомлений.
Реализуйте классы EmailNotifier и SMSNotifier, которые будут реализовывать интерфейс Notifier.
Перепишите класс NotificationService так, чтобы он зависел от абстракции, а не от конкретных реализаций.
Напишите демонстрационный код, показывающий работу вашего решения.
Обратите внимание на класс NotificationService в исходном коде. Он нарушает принцип инверсии зависимостей (DIP), так как напрямую зависит от конкретных реализаций EmailSender и SMSSender. Подумайте, как можно использовать абстракцию для устранения этой зависимости.

Создайте абстрактный базовый класс или интерфейс Notifier с методом notify(). Затем реализуйте конкретные классы EmailNotifier и SMSNotifier, которые будут наследоваться от этого базового класса или реализовывать этот интерфейс.

Измените класс NotificationService так, чтобы он принимал объект типа Notifier в конструкторе или методе отправки уведомления. Это позволит легко добавлять новые способы отправки уведомлений без изменения кода NotificationService.
